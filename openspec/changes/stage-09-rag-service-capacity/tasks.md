## 2. Implementation Plan

- [ ] 2.1 定义并实现短问答及长任务提交/查询/取消的FastAPI契约，区分生命周期与complete/partial/error结果；验收：正常返回、待澄清、未知task_id、partial/error和范围/snapshot可见的契约测试，202和HTTP200不自动计成功。
- [ ] 2.2 实现PG任务持久记录与可靠投递恢复，保存scope、snapshot、进度、deadline、尝试、取消及执行代次；验收：持久化后未入队、重复投递和worker崩溃场景均可重新发现任务，无仅存在内存的已接受长任务。
- [ ] 2.3 实现请求幂等和断点恢复，恢复沿用原scope/snapshot与累计预算，外部写入以稳定身份幂等；验收：同键同输入同task_id、同键不同输入冲突、重复领取不重写条目、撤销来源不换版本凑齐的测试。
- [ ] 2.4 实现请求大小/范围/token准入、有界队列、最长等待及短长任务配额；验收：超限明确拒绝、无静默截断和无界堆积，热缓存请求仍计入API资源，饱和行为有可核查记录。
- [ ] 2.5 将stage-04调用限额扩为跨worker共享inflight/RPM/TPM与费用控制，覆盖embedding/重排/生成、缓存回源、重试和恢复；验收：多worker竞争、保守token预留与结算、配额未知/协调故障拒绝、失联调用不立即释放占用的测试。
- [ ] 2.6 实现总deadline、单次调用超时、有限退避重试和累计预算；验收：429/网络故障有界恢复，权限/校验错误不盲重试，重启不重置次数，达到任一上限明确partial/error并记录费用。
- [ ] 2.7 实现持久取消、终态保护和迟到响应隔离；验收：排队取消不派发、运行取消停止新工作、重复取消幂等，迟到响应不改成complete，远端取消不确定性与有效部分结果均保留。
- [ ] 2.8 建立脱敏任务/请求/模型配额观测并对齐缓存事件口径；验收：到达至终态事件、scope/snapshot、全部状态、队列/任务/模型inflight、token与费用可对账，缺失事件有原因，不记录密钥或受限原文。
