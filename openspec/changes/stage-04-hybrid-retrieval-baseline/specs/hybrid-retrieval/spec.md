## Purpose

本能力在固定地区、时间、内容与解析版本范围内建立可复核的混合检索基线，通过词法或稀疏及稠密候选、排名融合、重排、父章节和原文引用形成回答，同时记录各阶段证据与失败，防止错误版本、模型协议猜测或离线冒烟结果被误当作真实可复现的RAG质量基线。

## ADDED Requirements

### Requirement: 真实模型协议与授权预算门槛

系统 MUST 在真实运行前分别核实 chat/embed/rerank 的协议、模型、输入输出约束、embedding 维度、重排映射、配额与预算，并确认数据外发许可；调用 SHALL 有超时、有限重试与停止条件，不输出秘密或猜测兼容接口。

#### Scenario: 已获授权的三类接口完成核实

- **WHEN** 三类能力分别具备安全配置、数据许可、配额/费用上限及小样本真实协议证据
- **THEN** 系统按已验证配置调用并保存脱敏溯源、模型限制与预算使用情况，不将某一服务支持的格式自动套用到其他服务。

#### Scenario: 接口未核实或达到配额预算边界

- **WHEN** 某必需协议/授权未确认，或出现认证失败、持续限额、超时重试耗尽、预算触顶
- **THEN** 系统停止或拒绝相应真实调用，记录阻塞/失败和已发生用量，不自动换模型、增加额度或以离线回放冒充真实请求。

### Requirement: 固定 Scope 与初始 Snapshot

系统 SHALL 在查询开始前固定显式地区/时点/版本 scope 及经映射校验的不可变初始 snapshot，绑定内容版本、解析视图、源块集合、词法与 Qdrant 索引修订及 embedding 配置；完整在线发布协议不属于本能力。

#### Scenario: 同一请求读取冻结视图

- **WHEN** 两路检索、PG原文读取、父章节和生成在同一请求内执行
- **THEN** 全链路使用相同 snapshot 和 scope，运行中不修改其索引或追随 latest，历史问题只使用其已确认适用的版本；未通过构建校验的快照不能用于运行。

#### Scenario: 范围歧义或版本视图不匹配

- **WHEN** 范围缺失/有歧义、法律日期 unknown，或任一来源不属于指定内容/解析/索引视图
- **THEN** 系统返回明确澄清/范围未决或版本错误，隔离非法候选，整体范围不可信时不输出成功答案，不由 Top K 默默补范围或回退最新版本。

### Requirement: Qdrant 映射及词法稠密双路检索

系统 SHALL 使用具有固定模型维度的 Qdrant 稠密索引和经核实的词法/稀疏通道，每路返回可映射 PG 原文的候选及路内排名；索引构建 MUST 可重复且不增加重复映射，不能以索引摘要或点 ID 替代原文块身份。

#### Scenario: 两路候选与重复构建

- **WHEN** 授权语料完成索引并对文号、数字/单位或语义问题检索，或相同索引批次重复构建
- **THEN** 两路只返回同范围同快照的可定位原文候选，保存各路排名与配置；重复构建不增加点或改变逻辑来源映射，同身份不同内容显式冲突。

#### Scenario: 错误维度或孤立来源映射

- **WHEN** 文档/查询向量与索引维度或编码配置不匹配，或召回点找不到合法原文来源
- **THEN** 系统明确拒绝该向量或隔离孤立候选并记录原因，不补零/截断向量、不静默重建集合，也不把无映射候选送入答案上下文。

### Requirement: RRF 重排与父章节引用链路

系统 SHALL 在路内去重后执行参数固定的外层 RRF、经验证的 rerank 和预算内父章节扩展，最终证据 MUST 回到同 scope/snapshot 的 PG 原文，并保留排序、扩展和裁剪记录。

#### Scenario: 候选融合后生成有来源回答

- **WHEN** 合法候选从两路进入融合、重排和父章节扩展
- **THEN** 相同来源不因切片重复加权，路内排名而非异构原始分数参与 RRF，父章节按固定解析视图读取，回答引用具备可校验 block/版本/页和原文文本，不把父章节称为全文枚举。

#### Scenario: 重排协议异常或上下文超预算

- **WHEN** 重排响应无法对应输入、包含非法重复结果，或父章节上下文超过已冻结预算
- **THEN** 协议异常形成明确失败而非猜测结果；合法预算裁剪保留被删块与原因及范围限制，不跨版本补上下文，不将裁剪后的回答无条件称为全部政策。

### Requirement: 全题失败状态与保守无答案

系统 MUST 为正式题集每题保存 complete/partial/error 及实际原因，必需模型阶段失败不得静默降级后仍冒充 A 成功；无答案 SHALL 与模型错误、范围未决和解析不完整明确区分。

#### Scenario: Embedding 或 Rerank 或 Chat 调用失败

- **WHEN** 任一必需模型阶段失败、超时或重试耗尽
- **THEN** 该题保留 error 或明确 partial、失败阶段和已完成证据，不能丢题或将空输出判为无答案正确；其他路线降级若单独试验须另分运行，不计作完整 A。

#### Scenario: 链路成功但没有支持答案的证据

- **WHEN** scope 已确定、规定流程成功结束而固定范围内未找到足够支持证据
- **THEN** 系统返回明确无答案和空条目并保留检索范围限制，不编造条款；若存在未解决解析缺口或处理失败则显示相应限制/未完成状态，不声称现实世界无相关政策。

### Requirement: 阶段 Trace 与真实基线证据

系统 SHALL 保存解析/已保存块来源、各路候选、融合、重排、父章节、最终上下文及答案的可关联 trace 和删除原因，并按独立评测协议保留全部预测、judgments、配置与实际调用证据；旧生产配置不足时 MUST 标为重建 A 基线，封存集不足时不得宣称独立测试质量。

#### Scenario: 对漏掉的 Gold 进行阶段归因

- **WHEN** 运行后人工发现一个 gold 未被正确回答
- **THEN** 可依据冻结来源和逐阶段 ID/版本清单定位证据最早未出现或被移除的位置，区分解析/召回/重排/预算/生成缺口，证据不足则标待复核，不把 gold 提前加入检索或仅凭最终答案猜原因。

#### Scenario: 交付真实运行或受限开发结果

- **WHEN** 汇总基线配置、全题预测、失败、人工裁决、逐题指标和构建/查询成本
- **THEN** 报告按 public/synthetic 与 split 分开，记录数据/代码/模型/维度/索引/预算及缓存关闭状态；真实请求和回放/demo 清楚区分，未知旧生产配置时名称为重建 A，缺独立 holdout 时只交付开发诊断，单独评分 JSON 不认证模型 benchmark。
