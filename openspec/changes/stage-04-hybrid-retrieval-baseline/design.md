## Context

[步骤](../../../docs/04-step-by-step.md)与[四组对照](../../../docs/06-evaluation-and-load-test.md)定义 A 为混合检索、RRF、rerank、父章节召回；A 是后续图路 B、完整性路径 C 和组合 D 的比较基础。[架构](../../../docs/01-architecture-and-stack.md)强调各通道先映射原文块、按排名融合，图描述或索引摘要不能作为最终证据。

现有事实只支持“已有离线验证/评分工具、8份PDF共139页已复制”；首批 air-01/water-02/air-03 共28页未解析。PG/Qdrant/Redis 由用户部署于 Apple Container，但项目未连接。chat/embed/rerank 的服务、真实接口、模型、维度、配额和预算未确认，上游存储与人工题集也未实现。原生产配置不可得时不得承诺精确复现旧链路。

本轮仅文档规划，不联网、不调用模型、不安装、不启动容器、不读 `.env`/密钥、不改原 docs。下述新增实现目录、测试和运行证据均待创建。

## Goals / Non-Goals

**Goals**

- 在经授权的小样本上建立真实 A 基线，固定语料、内容/解析版本、模型、索引、参数与上下文预算。
- 词法与稠密候选同范围融合，重排和父章节之后仍能回到 PG 原文引用。
- 固定 scope 与初始 snapshot，阻止错误版本、错误维度和无来源候选被静默采纳。
- 用逐阶段 trace、全题预测和独立裁决解释遗漏、失败与实际成本。

**Non-Goals**

- 不实现图候选、范围内逐章枚举、语义缓存、Redis服务治理或容量压测。
- 不实现完整多库索引更新、发布、删除与回滚协议；这些属于 `stage-07-versioned-index-updates`。
- 不保证 Top K 或父章节扩展提供全部政策条目，不以更换组件后的本地实验充作精确生产复现。
- 不把已有首批 MinerU 上传意向扩展为 chat/embed/rerank 外发许可或新付费授权。

## Decisions

### 1. 先核实三个真实接口，再写适配

未来分别核查 chat、embedding、rerank 的服务主机/协议、鉴权方式、实际模型 ID、请求与响应格式、批量能力、长度限制、embedding 维度、重排结果对应输入的规则、RPM/TPM/并发和收费单位。必须记录脱敏的授权小样本请求/响应、供应商说明与实际行为差异，不假定 OpenAI 兼容或三个能力由同一服务提供；本设计不写猜测 endpoint 或方法签名。

首次探测前确认文本外发范围、凭证在进程内安全提供、最大请求数、时间/token/费用上限、超时及有限重试次数。配额不足、429持续、认证失败或预算触顶应有界停止，不能自动换未授权模型或放大批量。秘密不进入日志、命令参数和证据包。接口尚未确认时只可做明确标注的离线回放测试，不能称为真实 A 运行。

### 2. Qdrant 只保存可追溯的索引，不取代 PG

复用用户既有 Qdrant 的隔离集合/命名空间，实施前确认准确实例与安全连接，不重装、不清库。向量维度和距离度量以确认后的 embedding 配置固定；文本和查询必须使用匹配的模型/配置，维度不符直接拒绝，不补零、截断或悄悄重建集合。

每个索引点关联索引修订、内容版本、解析版本与一个或多个有明确边界的源 block ID；保留分块/变换指纹和索引块到原文块映射。重复构建同一初始批次保持相同逻辑映射与点数量；同身份不同内容显式冲突。召回前按已解析 scope 过滤，召回后再对 PG 校验映射、解析视图和适用版本；孤立映射、错误版本或内容不一致不得进入上下文。

A 优先沿用 stage-02 的分块；如必须再切分，记录边界与来源，不能换分块后不承认基线变化。原文从 PG 获取，索引 payload、框架摘要和排名不能独自构成引用证据。

### 3. 最小词法/稀疏通道与稠密通道

先核实既有可复现词法方案和 Qdrant 的真实稀疏能力；可用时复用其固定实现。若无可核实实现，允许在小样本中选择明确命名、版本固定的本地词法基线，而不是为本阶段新装 OpenSearch。选型必须在开发集运行前记录，不能假称旧生产 BM25/分词配置已被还原。

词法通道重点验证中文切分、政策文号、标准编号、数字与单位；稠密通道固定文档/查询编码配置。每路输出原文块映射和路内 rank，并保存原始分值但不直接相加。两路有效范围、版本及初始 snapshot 完全一致；同一路重复点先按来源去重，避免一块因多个切片或框架重复检索在融合中被重复加权。

### 4. 可解释的 RRF、重排、父章节与引用

外层 RRF 基于各路排名，记录候选数、融合常数/权重、确定性的并列处理和去重规则，均在开发阶段选择后冻结。LightRAG 如早期用于转换或其他已核实组件，只复用必要能力；本 A 不启用图候选，也不把 LightRAG 内部 hybrid/mix 当作外层 RRF。

重排只对已校验的融合候选执行，按已核实协议解析结果；未知输入索引、重复项或畸形分数视作协议失败，不猜测对应项。重排后通过 stage-02 的固定解析视图扩展父章节，再按预算组装原文上下文，保留所加/所删块与原因、内容长度及使用 token 信息。不得跨 scope 拉入相邻文档/版本，不将父章节扩展解释为全文枚举。

回答需给出范围、版本、条目及可回查原文的引用；检查 block ID、版本、页定位和 quote 存在，语义支持最终由 stage-03 独立 judgments 确认。上下文裁剪必须记 trace；普通检索完成不等于枚举完整。材料或处理不完整时显示限制；不能输出无条件“全部措施”。

### 5. 最小不可变初始 snapshot，不提前实现 stage-07

请求开始前用显式 scope 固定地区、有效时点及版本集合，并映射到唯一内容/解析视图。歧义、未知日期、缺少版本依据时返回需要澄清/范围无法确定的明确状态，不由 Top K 隐式决定范围。对既有 predictions 的兼容映射采用 error 或有明确未完成原因的 partial，不把范围未决伪装成合法无答案。

基线使用预先完成映射校验的单批次不可变 snapshot，清单绑定允许的内容/解析版本、源块集合哈希、Qdrant 集合/索引修订、词法修订、embedding 配置。构建/检查未完成的清单不可用于 A 运行；运行开始后不改该批次索引，不依赖会漂移的“latest”别名。所有通道、PG 原文读取、父章节扩展、生成与 trace 携带同一 snapshot 标识；请求中遇到不匹配须拒绝，不能重取最新数据凑答案。

这里仅冻结单次基线输入并验证一致性，不宣称 PG/Qdrant 已有分布式事务、在线原子发布或恢复保证。完整构建状态机、多库发布、回滚、失效与删除由 [stage-07](../stage-07-versioned-index-updates/proposal.md) 负责，不是本变更前置依赖；后续应迁移而非并行发明另一套发布语义。

### 6. 显式失败与保守无答案

错误版本/维度/孤立映射在调用生成前拒绝；若一条候选被过滤可继续处理其他合法候选，但范围/映射整体不可信必须阻止成功答复。必需的 embed/rerank/chat 失败默认该题 error 或 partial，保留阶段和已完成工作，不静默用纯词法、无重排或换模型结果冒充完整 A。若未来开展降级诊断，另设配置和运行组，不混入 A 的成功统计。

在 scope 已确定、规定链路成功且无足够支持证据时可以返回明确无答案与空条目，说明只是固定范围/基线未找到支持，不声称现实世界没有相关政策。失败或超时导致的空输出为 error，不能算无答案正确。预算裁剪和 partial 解析所致不确定性必须显示，不能藏在 complete 标记下冒充完整覆盖。

### 7. Trace 与真实 A 证据包

按 run/case/snapshot 记录解析输出/已保存集合清单关联、每路候选及 rank、融合后、重排后、父章节扩展后、最终上下文和答案条目；各阶段保留版本、来源通道与删除原因，包括范围过滤、映射失效、去重、重排淘汰、预算裁剪、模型失败。原件/解析证据由上游提供，缺失时标未知，不能仅凭最终答案推断解析遗漏。

Gold 只用于运行后的诊断，不进入候选选择或提示。对每个漏项追踪其一个或多个可接受证据集合，判断最早缺失/被移除的阶段；证据已入上下文而答案未写出应标生成阶段遗漏，原因不确定时保留待人工复核。相关 trace 只记授权可保存内容，必要时保存 ID/哈希并由本地样本映射回查。

A 的开发运行冻结语料、分块、模型/重排、候选数、RRF、上下文预算和 Prompt 配置；关闭检索/答案缓存，记录缓存状态，未来比较不让缓存遮蔽改动。以实际调用构建预测，每个正式 case 都有 complete/partial/error；再按 stage-03 人工裁决和计分。运行清单包括 dataset_kind、split、数据/代码/解析/索引/模型版本、请求协议、维度、预算、是否实际调用、时间和裁决方法。构建成本与查询成本分开；供应商未返回的 usage 或成本明确未知，不虚造精度或延迟。

若旧生产关键配置缺失，运行名称使用“重建 A 基线”，列出已确认、替代、未知项；只有后续证据充分且配置一致才讨论精确复现。若 stage-03 无独立封存集，则只报告开发结果和逐题限制，封存质量结论仍阻塞。离线 demo 不升级成 A benchmark，评分器单独 JSON 仍不认证执行来源。

## Risks / Trade-offs

- 模型接口、维度、限额及预算未知：必须在实现前逐项确认；当前不能提供可直接运行的供应商调用命令。
- 上游解析/人工 gold 未交付：可准备接口与 trace 设计，不可用伪造预测充当真实基线。
- 固定初始 snapshot 限制在线更新，但能避免在 stage-07 前引入未经验证的多库一致性假设。
- 中文词法实现差异和父章节 token 增长可能显著影响 A；记录选择与预算，不把更多上下文的收益归因于融合算法。
- 分块改变和重复来源会夸大 RRF 权重：来源映射与路内去重必须先于排名融合。
- 小样本难以形成独立 holdout，开发结果仅用于诊断；不以已知公司规模或未核实简历指标补齐证据。

## Migration Plan

先审阅两项前置验收与授权，核实模型协议，再在隔离索引中构建固定小样本视图；用确定性回放验证失败处理并明确非端到端，之后才执行获准的真实 A。每次数据/参数变化创建新的运行与索引修订，不覆盖旧证据；旧生产未知配置列差异。未来 stage-07 接管发布语义时保留 snapshot 溯源兼容，不在本阶段修改其设计或实现。
