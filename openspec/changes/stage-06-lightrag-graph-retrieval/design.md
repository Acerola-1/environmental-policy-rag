## Context

本阶段验证图关联的独立贡献：B 是 A 加图候选，D 是 C 加图线索；图不是新的政策事实源。现有项目尚无 LightRAG、业务存储、真实 A/C 或模型评测，仅有离线脚本和 8 份、139 页 PDF；3 份、28 页首批未解析。框架教程和论文不能作为本项目收益证据。

技术参考：[架构](../../../docs/01-architecture-and-stack.md)、[路线](../../../docs/04-step-by-step.md)、[数据契约](../../../docs/05-data-contracts.md)、[评测](../../../docs/06-evaluation-and-load-test.md)、[验收](../../../docs/07-acceptance-and-evidence.md)。以下适配、trace、候选字段和交付位置均是计划，尚无可运行接口。

## Goals / Non-Goals

### Goals

- 用固定版本、可验证来源和同快照过滤的图候选补充 A/C。
- 让每个图候选、融合贡献及最终条目均能追到 PG 原文块和独立裁决。
- 控制重复信号与实验混杂，报告图独有有效项、无效项、质量差异和完整成本。
- 给 stage-07 交付实际支持的隔离、更新、删除及共享来源行为边界。

### Non-Goals

- 不承诺图能提高召回，不强制采用图作为生产默认路线。
- 不用图 summary 作为证据，不让图发现扩大用户未确认的 scope，不用图取代 C 全量遍历。
- 不默认安装 Neo4j 或其他图数据库；RAG-Anything 非必需，LangGraph 亦非本阶段门槛。
- 本轮仅规划，不联网查询版本、不安装、不读密钥、不构图、不启动已有服务、不调用模型或运行测试。

## Decisions

### 1. 版本与能力先核实，后选后端

实施前固定一个明确的 LightRAG 发布版本/提交与依赖锁定结果，记录实际 API、hybrid 候选输出、实体/关系来源 chunk、MinerU 输入转换、增量/删除及可隔离图数据的能力。当前不编造版本号或不存在的方法签名，精确版本是阻塞项。解析转换只做转换，不因导入框架就隐式构图或调用额外模型。

后端依据该固定版本的实测能力、现有环境和隔离/来源保留需求决定；用户的 Apple Container 中仅确认 PG/Qdrant/Redis 已部署，项目未连接，不能推定某图插件或数据库已就绪。优先最小可验证方案，新增部署必须另获授权。先核实原生转换是否够用，仅当真实产物无法满足块映射时才评估 RAG-Anything，并记录依赖及成本差异。

原因：最新版教程不等于实际安装协议。替代方案是直接跟随 main、默认某后端或同时引入多模态框架，会扩大未知条件，故不用。若后端不支持安全隔离或可追溯来源，明确阻塞，不能拿 summary 代替缺失能力。

### 2. 图来源统一回到 PG 原文身份

计划映射记录至少关联图构建标识、实体/关系来源 chunk、doc_id、内容 version_id、解析版本、一个或多个 block_id 及 snapshot。一个 chunk 可覆盖多个原文块，一个块也可被多个实体/关系引用；保留多对多来源，不以向量 point ID 或实体名充当原文身份。

图返回后先做来源展开、固定快照/地区/时间/文档类型过滤，再读取 PG 对应原文。不能定位、引用越界或混版的候选进入拒绝 trace；实体/关系生成描述仅供发现线索，不进入证据字段。最终引用必须是原文 quote 和页码，引用存在还需独立语义复核。当前 C 的逻辑 snapshot 沿用上游清单，不把 stage-07 作为本阶段前置。

原因：图汇总可能混合多文件、跨版本信息。替代方案是直接输出 LightRAG 答案或摘要，无法证明适用性及出处，故不接受。

### 3. hybrid 图候选与外层 RRF 分工明确

本阶段图路选择经实际核实的 hybrid 来源候选，不调用最终答案替代候选接口。实体/关系命中先按原文块路内去重，同一路同一块只提供一个有效 rank，保留全部来源 trace；与 stage-04 的词法、外部向量候选统一身份后，在应用层执行 RRF，融合后每个块只占一个候选位置，保留各独立通道的贡献和参数。原始分数不直接相加，LightRAG 原生 hybrid 也不宣称是 RRF。

外部向量路已存在时禁止配置 mix 再叠加其重复向量信号；应启动前拒绝这种组合，不能只在答案层去重。独立图证据与外部向量同时命中允许各计一次独立路贡献，但图内部多次实体命中不重复加分。所有路及重排最终候选再次检查 snapshot。

原因：答案去重不能修复排序时重复加权。替代方案是直接合并 mix 答案、原始评分或实体命中次数，无法解释收益，故不用。

### 4. 图只提供可观察的增量，不遮盖失败

B 仅在 A 的候选阶段增加图路；D 在 C 既定范围中增加图线索/复核优先级，不能少读任何原定章节，也不能自动加入范围外文件。外部线索可以作为范围外建议单独展示，确认后启动新 scope/snapshot 任务，不混入当前答案或当前对照。

图超时、来源不足或不可用时，按预先选定策略返回 error，或显式回退 A/C 并标注 graph_status、失败原因、实际执行路线；回退结果不能算成有效的图执行成功。重试有上限，图构建和查询均独立记账。

原因：静默降级会让 B/D 成功率和贡献失真。替代方案是任何失败都隐藏为普通答案，或无条件阻断全部基线查询；前者不可审计，后者降低可用性，故允许明确标注的受控回退。

### 5. 四组冻结配置，接受零收益和负收益

先从 stage-04 取得 A 和同题集/独立金标，再从 stage-05 取得 C。四组固定语料、内容/解析版本、分块、查询、embedding、rerank、生成模型/Prompt 和缓存策略；小样本消融优先关闭答案复用以免缓存掩盖路径。A/B 固定最终上下文预算与既有检索参数，C/D 固定全文扫描范围、抽取/生成规则与预算策略。图新增候选数、抽取模型与 Prompt、构建配置单独冻结；额外路的调用和 token 明示。C 相对 A 多读全文的差异不隐去。

开发集选择图参数后封存，不在测试集调参；公开与合成分别报告。对照输出 B 相对 A、D 相对 C 独有的唯一正确金标条目及证据，也记录新增错误、损失项、引用支持和错版本。不能把不同措辞或重复项算独有收益；失败/降级题仍留在全题统计并单列路线状态。

图构建的 token、费用、时间及存储与单次查询开销分开；说明摊销假设，不只报告缓存热查询。查询记录所有范围解释、图检索涉及的模型调用、重排、生成和重试开销；无 usage 或价格时标未知。增加成本而没有独有有效项、质量下降甚至映射能力不满足，都能形成有效的“不采用/暂缓”结论，而不是伪造提升。

原因：变量失控时不能归因于图。替代方案是换模型、增大上下文后只比总分，不能提供独立贡献证据，故不用。

## Risks / Trade-offs

- 固定版本可能不暴露所需来源或删除粒度；仅可增加最小适配并记录局限，不能许诺未验证能力。
- 图摘要跨版本混合、实体合并与缺失 chunk 是核心失败面，必须以原文映射过滤，而非信任生成文本。
- 路内去重与来源持久化增加成本，却是防止混版、重复计分及未来共享实体清理的前提。
- C 已遍历全部已保存块时图可能没有额外收益；仍需用独立裁决解释是否弥补抽取遗漏，不能改变范围制造提升。
- 获准后的模型实验需确认资料外发、接口、最大请求/token/费用及停止阈值；未授权不执行，构图不能挪用解析免费额度或旧授权。
- 精确版本、后端与预算尚未决定；目前只允许规划，不可为消除这些未知自行联网或启动服务。
