## Goals / Non-Goals

### Goals

- 将范围确认、版本固定、块遍历覆盖与语义条目召回分别记录。
- 对声明范围内全部已保存章节、表格、附件抽取条目，保留条件与出处；允许有限批次和分页，但不静默裁掉尾部。
- 支持失败可见、部分结果可用、同快照恢复不重复，并可追溯漏项发生阶段。
- 为 C/A 与后续 C/D 提供冻结配置、独立裁决与完整成本证据。

### Non-Goals

- 不保证现实世界文件收集齐全、解析无缺页或模型零漏抽；不以全量遍历替代独立语义评测。
- 不实现图检索、分布式服务容量、缓存、OCR 或 stage-07 的索引发布器。
- 本轮只写规划；没有模型调用、联网、安装、部署、服务启动、负载或项目测试授权，也不读取密钥。

## Decisions

### 1. 先确认 scope，再固定范围

计划 scope 至少说明地区及行政层级适用规则、时间语义（发布日期筛选或有效时点）、时间值/区间、文档类型、枚举对象（措施/标准）、显式文档/版本限制。默认 `as_of` 表示有效时点，不拿发布日期替代。上下级地区是否适用、日期未知、跨文件范围不明或用户说“所有政策”而目录有限时，返回待澄清及候选解释，不自动猜测。经确认的有限目录仍需输出目录限制。

原因：范围错误先于检索错误发生。替代方案是用 Top K 推断文件集合或默认全国/当前有效，虽简单但无法审计遗漏边界，故不用。

### 2. 固定不可变逻辑 snapshot，不等待未来发布系统

计划 snapshot 清单包含 scope 摘要、文档/内容版本、解析版本、预期有序 block_id 集合及哈希、目录/解析完整性标记、已有 A 索引配置标识。与 stage-02 核对身份规则后定版；同一内容重解析不得让旧 block_id 指向新文本。开始、分页、恢复均使用同一清单；目录出现新版本不改变在途任务。若旧块不可用或完整性无法验证，返回 partial/error 与缺失原因，不替换为当前版本。

原因：先实现可复现的只读范围，不把 stage-07 变成隐藏前置依赖。替代方案是每页查“最新版本”，会混版；一次性加载所有正文则受内存与模型上下文限制，均不采用。

### 3. 普通循环先行，状态机独立于编排框架

先按文档、章节和 block_order 有界读取所有已保存块；表格含续表/脚注，附件不因低相关性被跳过。抽取批次可组合相邻块，但每块必须有归属和处理记录。计划任务状态包括 run_id、scope、snapshot、pending/processed/failed 集合、尝试次数、已验证条目及 warnings；集合互斥并覆盖预期块，processed 可明确标记无相关项。

有失败、未处理、上游解析缺口或预算中断时输出 partial（无可用结果时可 error），并列明剩余范围。`complete` 仅表示本次声明处理流程已完成且已知输入缺口已处理，不表示语义零遗漏。页面截断必须提供续页及整体状态。批次结果与进度原子记账；同 run/snapshot/批次重试只追加尚未确认成果，已确认结果不被重复覆盖。

原因：最小循环足以验证核心语义。替代方案包括 LangGraph 或其他支持检查点的编排；仅在分支/恢复复杂度有实证需要时引入，且保持同样可观察状态。LangGraph 非唯一选择，检查点也不意味着外部调用恰好一次或全局限流。

### 4. 条目先保真，再去重与核验

计划条目保留 type、text、适用对象、conditions、value、unit、时间语义、version_id 和 evidence；evidence 包含 block_id、原文 quote、页码及定位。未知值明确标记，不补造阈值。完全重复项可合并但保留全部出处；语义近似项只有在对象、条件、数值、单位和适用时间一致时才允许合并，否则并列或进入人工复核。

先验证引用属于 snapshot、原文存在及版本/页码一致，再独立核验语义支持。失败候选保留拒绝原因，不充当已验证条目。生成环节仅组织已核验条目，不增加无出处结论；同一标准的不同条件、单位换算或跨版本关系不得仅凭名称折叠。

原因：短摘要会抹去限制条件。替代方案是抽取时压缩为答案或依赖引用子串自动裁决，不能证明条目正确，故不采用。

### 5. C 对 A 的同题可审计比较与费用门槛

继承同一题集/金标、snapshot、分块、模型、embedding、rerank、生成配置及明确缓存策略；仅引入枚举处理因素。A 的上下文预算不暗改，C 的分批全文读取属于显式差异，单列实际输入/输出 token、模型调用数、总时长、费用及相对 A 增量。保留失败、超时、partial 和无答案题；公开与合成分别出报告，封存测试不调参。

成本统计涵盖范围解释、抽取、核验、生成及重试；价格/usage 未知填未知，区分账单实测和估算，不填零费用冒充。正式执行前需再次确认可外发资料、接口与模型、最大请求/token、预算和停止条件。未授权一律不发请求；费用上限到达则停止并保存 partial 与断点，不自动充值、扩容或盲重提。离线回放只能证明流程，不能替代真实模型质量。

原因：C 可能因多读内容获益，必须同时说明代价。替代方案是只比召回率或强行宣称 token 相同，会掩盖成本，故不用。

## Risks / Trade-offs

- 有序读取只能覆盖已保存块；缺页、缺附件与目录不全分别记录，不能“processed=100%”即写全部正确。
- 细粒度状态与多出处保留增加存储和实现成本，但支持中断恢复、人工核验及错误归因。
- 重试可能在进度未提交前重复产生外部费用；设置有界重试，留请求标识和计费状态，不承诺恰好一次计费。
- 快照不可再现、日期未知或独立金标缺失都可能阻塞验收；不得用假日期或 demo 分数绕过。
- 输出覆盖与语义覆盖单独报告。即使 C 无增益或成本明显上升，也保留完整负面结果，而非编造成果。
