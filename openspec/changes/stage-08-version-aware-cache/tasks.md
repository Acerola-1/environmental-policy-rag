## 2. Implementation Plan

- [ ] 2.1 定义缓存层级与key schema，覆盖query、模式、范围/时点、固定用户namespace、授权域版本、会话、snapshot、检索/模型/Prompt/schema配置；验收：同身份与逐维度变化测试、安全规范化不删否定/数字/单位的用例，明确个人namespace不是RBAC。
- [ ] 2.2 实现精确答案缓存及准入门禁，禁止partial/error、未澄清、无答案、附件未解析、未授权和实时结果写入；验收：完整带引用答案命中且源调用为零，逐类禁写和重复请求测试均有记录。
- [ ] 2.3 实现检索结果缓存和权威块复核，不将候选齐全当枚举完成；验收：合法候选复用、缺块/版本越界/撤销来源拒绝及生成仍计数的测试。
- [ ] 2.4 实现TTL、独立绝对到期与snapshot/授权域/配置失效；验收：热点续期不越绝对期、新版本不命中旧key、历史适用版本隔离及删除撤销回归。
- [ ] 2.5 实现同key请求合并、唯一所有者、租期及陈旧写入隔离；验收：正常并发仅一次源填充，等待者单列coalesced，异常接管和安全释放不覆盖后继结果。
- [ ] 2.6 实现填充后snapshot复核与有界回源，复用stage-04限额且不等待stage-09；验收：填充中发布/删除、Redis故障、协调丢失、等待超时和预算耗尽时不写陈旧值、不无限重试的故障记录。
- [ ] 2.7 评估embedding缓存是否需要并记录决定，若实现则记录模型版本/配置/维度并隔离数据域；验收：未实现标不适用及理由，已实现提交重复命中、版本/维度变化miss和费用归因测试，不将解析去重算作问答收益。
- [ ] 2.8 建立语义影子模式、硬过滤及默认禁用规则，预先冻结允许模式、阈值方法、样本、错误复用和成本门槛；验收：枚举/阈值/跨版本比较禁复用，过期/缺失Redis候选miss的测试及可审计准入协议。
