## Context

事实基线是离线工具、8份139页PDF及尚未解析的首批3份28页。PostgreSQL、Qdrant、Redis由用户部署于Apple Container，但项目尚未验证连接；精确/语义缓存、检索服务和模型调用均未实现，没有生产指标。本轮仅编写规划，既有容器授权不扩展为本轮启动或访问许可。

输入契约来自stage-04的基线与基础调用限额、stage-05的范围和执行状态、stage-07的已发布snapshot与失效事件。保留[存储与缓存](../../../docs/09-storage-and-cache.md)、[评测与负载](../../../docs/06-evaluation-and-load-test.md)、[验收与证据](../../../docs/07-acceptance-and-evidence.md)原文，不回写其历史状态。

## Goals / Non-Goals

### Goals

- 使精确复用可观察、可隔离、可失效，故障时不能返回未知版本答案。
- 在已有调用限额下减少实际源调用，分别量化命中、请求合并、质量风险及成本。
- 用独立影子评估决定语义复用；未达准入时保持关闭是合法结论。

### Non-Goals

- 不实现生产RBAC、UI、生产部署或任意范围的数据上传。
- 不把TTL当授权机制，不用缓存替代PG原文、版本目录或枚举覆盖判断。
- 不在本阶段建立API容量承诺；不依赖stage-09才获得基本模型限额。
- 不承诺语义缓存必启用、命中率目标必达、负载或质量必提升。

## Decisions

### 1. 先核实复用能力，再补业务边界

本地已核实的现有工具是标准库实现的JSONL校验、人工裁决评分及其测试；未发现项目依赖清单或已接入缓存框架。这只说明现状，不是拒绝依赖的理由。后续实现前比较固定版本的redis-py异步访问/原子操作能力、Qdrant客户端过滤能力和现成缓存库；记录接口、兼容性、许可证、错误行为与最小适配点。RedisVL仅作为语义缓存候选，不能未经比较就与Qdrant重复建设向量缓存。当前不联网或安装，具体版本与可用API仍待核实。

原因：复用传输、超时与原子原语比自造客户端稳妥，但通用缓存不能替代本项目的快照和范围规则。替代方案是直接使用框架默认缓存；因其键和状态门禁未核实，不直接采用。

### 2. 键是可审计的请求身份，而不只是query hash

计划按稳定序列化结果生成带版本的key；原始问题和敏感文本不直接写入Redis键或日志。身份至少包括：

| 维度 | 规则 |
|---|---|
| 数据与授权域 | namespace、dataset_kind、user_scope、authorization_epoch；个人阶段固定本地namespace/user_scope，不接受调用方任意改写，不代表RBAC |
| 查询 | 安全规范化query、query_mode；保留日期、否定、数字、单位和条件 |
| 范围 | 地区、时间语义、解析后的具体时点、文档/版本范围；“今年/最新”先解析，未知则不读写答案缓存 |
| 会话 | 与当前上下文绑定的conversation digest及其规则版本；不能把指代问题作为独立文本复用 |
| 知识 | 从PG固定的已发布knowledge_snapshot_id；历史法律版本、当前索引snapshot、解析版本分别保留 |
| 配置 | 检索配置（含top-k/融合/重排）、embedding与reranker版本、回答模型、Prompt、输出schema版本 |

精确答案与检索缓存分层命名，不把相似问题当精确相同。检索缓存保留候选block ID、version ID、排序与配置，命中后回权威原文校验可读性、范围、存在性；不能将候选齐全当枚举已完成。首版允许保守地使用相同完整身份，避免为提高命中率省略维度。

若实现embedding缓存，还必须记录规范化输入、embedding模型/配置版本和维度，并继承数据隔离；维度变化强制miss或更换兼容命名空间。不将文档解析去重算成问答缓存收益。

原因：范围和版本正确性比命中率优先。替代方案是仅query哈希或删去条件的激进规范化，存在跨年、跨域、否定反转风险，拒绝采用。

### 3. 准入、TTL与snapshot双重校验

答案仅在status=complete、范围已澄清、引用可核验且有可复用答案时写入。partial/error、无答案、待澄清、附件未解析、未授权内容和实时工具结果首版禁写；历史旧条目若不符合新准入规则也不得命中。检索中间结果仅在候选阶段自身完整且校验通过时写入，不受回答生成成功的假象影响。

缓存记录创建时间、TTL期限和独立绝对到期时间，读取时以较早期限为准；续期不能突破绝对最大年龄。版本/授权域/配置变化直接改变身份，删除或撤销可读性即刻按权威目录拒绝，不等待TTL。

填充开始固定snapshot，完成后再核对发布状态与引用可读性。若当前snapshot已切换，首版丢弃本次缓存填充，不将旧结果写入新key。既有请求只可返回明确标注其原snapshot且仍可读的结果；被删除或撤销的来源不得继续服务，按状态契约拒绝或在有界预算内重新执行，不静默拼接新旧证据。新请求始终固定新的已发布snapshot。历史查询另由适用性规则选择合法版本。

原因：异步失效通知不等于强一致；PG目录为权威，Redis镜像指针不能独立决定新鲜度。替代方案是通知删除+滑动TTL，可能让热点旧结果无限存活，拒绝采用。

### 4. 请求合并不绕过限额，失败不无限回源

同key并发miss只产生一个有效填充所有者，其余请求有界等待。跨进程协调采用唯一所有者、租期和栅栏标识，安全释放必须确认所有权；过期所有者不得覆盖新结果。正常情况下只执行一次源链路；租约丢失等异常可能出现重复外部调用，必须受限并如实记录，不能承诺恰好一次。

等待超时、Redis不可用或填充失败时，按配置尝试有限回源或明确返回partial/error/拒绝原因，不无限排队/重试。所有embedding、重排和生成仍通过stage-04基础并发、RPM/TPM、超时与预算门禁；协调或限额状态无法确认时保守拒绝。stage-09负责将此约束扩为API及跨worker治理，而非本阶段依赖。

原因：缓存击穿可能放大供应商调用。替代方案是每个等待者立即独立回源，或使用无期限锁，分别造成调用风暴和永久挂起，不采用。

### 5. 语义缓存只通过证据升级

先对范围一致的普通概念问答做影子候选查找，不影响线上/实际回答。硬过滤使用同一数据域、scope、snapshot、会话及配置；检查数字、否定、主体、时间和条件差异。枚举、标准阈值、跨版本比较默认禁用语义答案复用，不能由相似分数绕过。

若需要向量候选，优先评估现有Qdrant的独立集合；Redis承载答案。向量候选必须再次通过Redis存在性、绝对期限、引用与snapshot校验；失配按miss，残留向量清理只是维护手段。相似度和距离方向由实测API核实，不能照搬固定阈值。

准入在实验前冻结允许模式、阈值选取方法、样本量、错误复用上限和成本/延迟容忍度；跨范围/版本/过期复用为零容忍项。开发集选阈值，独立题集及人工裁决核验；样本不足或未达门槛继续关闭，可验收“安全关闭策略”，但不能写“语义复用已启用/已提升”。缺少调用授权时真实影子评估保持未执行，只能交付关闭配置与边界证据。

原因：语义相似不等于答案可替换。替代方案是立即启用语义缓存追求命中率，质量风险不可接受。

### 6. 统计区分请求、层级命中和实际调用

精确答案/检索/embedding/语义各层分别记录lookup、hit、miss及分母；合并等待者记录coalesced，不记作缓存命中，即使其随后读取填充结果。源调用按embedding、检索、重排、生成分开计数；请求重试也计入实际调用。

以同配置、同样本的无缓存对照核算跳过调用数；合并节省单独归因，不与cache hit重复累加。语义查找的embedding成本和供应商Prompt缓存单列。报告冷缓存、精确重复热缓存、近义改写、范围冲突、版本更新和自然重复分布；无自然样本时标未执行，不伪造真实用户分布。算法消融禁止复用旧配置答案。

原因：Redis读取快不代表端到端快。替代方案是用单一总命中率代表收益，无法解释成本与错误，不采用。

## Risks / Trade-offs

- 保守的完整键降低命中率、增加PG校验开销，但优先避免错误复用；数值需实测，不能预填提升。
- 跨系统发布与Redis写入不是事务；使用请求固定snapshot、读取复核和丢弃陈旧填充，不能宣称Redis通知提供强一致。
- 锁过期后的重复调用可能收费；限额、所有权校验与费用日志共同约束，不将单次填充承诺扩大为恰好一次执行。
- 影子实验也可能调用模型或外发数据；未获许可不执行。回放只能证明逻辑，不能证明真实质量/容量。
- TTL数值、语义阈值、具体库版本和回源预算尚待上游证据与授权后确定，未确定时不开启相应实验。

## Handoff

### Entry

接手先按[proposal依赖](proposal.md#dependencies)检查stage-04、stage-05、stage-07验收记录，再执行[tasks](tasks.md)的权限与库核实任务。OpenSpec不自动强制这些跨change门禁；CLI产物状态不是业务验收。

### Blockers

上游检索、枚举及snapshot接口尚未实现；模型协议、额度、可外发数据范围和服务连接未核验。总入口见 [OpenSpec导航](../../README.md)，具体依赖见本变更proposal；文档已齐全不代表上游实现已验收。后续执行依当次授权推进，本轮仅保留规划。

### Evidence

以下均为未来待创建产物，本轮不创建：

- `runs/<dataset-kind>/<run-id>/cache-manifest.json`：代码、配置、库版本、key schema、TTL/绝对期限、权限与预算引用。
- `runs/<dataset-kind>/<run-id>/cache-events.jsonl`：层级命中/合并、源调用、填充所有权、失效、故障、最终状态的脱敏记录。
- `runs/<dataset-kind>/<run-id>/cache-regressions.json`：范围、会话、版本、状态、过期、故障和并发边界证据。
- `runs/<dataset-kind>/<run-id>/semantic-shadow.jsonl`：候选、独立裁决、阈值与继续关闭/允许启用的决定；未执行时仅在验收矩阵标原因，不生成假结果。

向stage-09交接缓存事件口径、有界回源约束和固定snapshot行为；向stage-10交接真实证据与未完成项，不交接假定的性能提升。原docs不修改。
