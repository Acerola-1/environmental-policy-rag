## 1. Entry and Contracts

- [ ] 1.1 读取本 change 及 stage-02-versioned-document-store、stage-04-hybrid-retrieval-baseline、stage-06-lightrag-graph-retrieval 已验收交付后再开始实现；验收：人工依赖清单含代码/数据/配置、块读取、图后端能力及测试证据，缺项保持阻塞。
- [ ] 1.2 对齐内容哈希、政策内容版本、法律元数据修订、解析版本、generation、snapshot 和发布序号，确认历史/删除策略与执行授权；验收：身份语义表、同内容重解析/同哈希法律更正用例及预算门槛；本轮不实现或接入服务。

## 2. Build and Publish

- [ ] 2.1 建立具有幂等键、期望父发布序号、尝试代次和逐阶段状态的 PG 更新账本；验收：重复提交、并发恢复和过期 worker 状态写入被拒绝测试，不把账本成功当外部成功。
- [ ] 2.2 基于上游实测能力选择可隔离的原文/向量/图 generation，保留旧资源且不默认另装图数据库；验收：新构建不改变旧查询的对照，若后端不支持隔离则给阻塞或获准全量隔离重建证据。
- [ ] 2.3 实现原文映射、Qdrant 与 LightRAG 分阶段幂等构建和有界重试；验收：外部写后记账前中断、向量成功图失败、重复写入恢复记录与 token/费用明细，旧 snapshot 持续可读。
- [ ] 2.4 校验预期块集合、内容/解析身份、索引配置、图来源、引用与实际可读性，生成不可变 snapshot 清单；验收：正常完整构建通过，缺失/孤立/混版/残留候选阻止发布的测试。
- [ ] 2.5 仅在 PG 事务内原子发布清单/记录/指针，读者统一采用该发布视图，不依赖逐库 alias；验收：发布前后各路一致性、事务失败指针不变及校验后回退使用新发布序号测试。

## 3. Snapshot and Concurrency

- [ ] 3.1 实现两个发布者的 expected_revision 竞争、冲突记录与重算校验；验收：受控并发时序中仅一个成功，失败者不覆盖胜出更新、不会盲重试造成丢更新；不运行负载测试替代此回归。
- [ ] 3.2 实现取得发布视图与持久引用/租约的同步保护及分页、恢复固定 snapshot；验收：长枚举跨更新、同内容重解析、旧查询新查询并行均不混版，旧 block_id 文本不变。
- [ ] 3.3 实现历史快照保留、共享 generation 引用与 GC 标记/续租/释放协议；验收：读者获取与 deleting 竞争、有引用不删、过期租约停止读取、重启恢复和历史已清理显式不可用测试。

## 4. Lifecycle and Handoff

- [ ] 4.1 分别实现新增、修订、废止和获准逻辑删除，独立核实生效/替代关系；验收：四类操作当前/历史时点及指定快照查询对照，未知法律日期不编造，废止不等于物理删除。
- [ ] 4.2 按来源贡献执行共享图实体/关系清理及逐库可重试删除，不覆盖保留历史；验收：单来源删除、多来源保留、向量删后图失败再恢复、重复删除和未获物理删除授权被拦截测试。
- [ ] 4.3 提供独立发布版本接口与计划响应，供 stage-08 将 snapshot/publication_revision 纳入缓存 key；验收：内容/解析/法律元数据/索引配置更新及回退均更新标识，重复完成任务不多发，无 Redis 或 stage-08 仍可用。
- [ ] 4.4 在另行授权环境完成故障矩阵与证据整理，区分构建完成、已发布和清理完成；验收：PG/Qdrant/LightRAG 部分失败、发布竞争、逻辑引用/GC、历史查询和重试的原始记录，未运行项标未执行，不伪称跨库事务。
- [ ] 4.5 按 G5-1/G5-2 交接下一 Agent 的 stage-08 入口、发布契约、冻结上游版本及限制；验收：任务/快照/发布/引用/清理日志和测试证据索引齐全，依赖仅人工核查且无 stage-08 反向依赖，不以 artifact 写完算实现完成。
