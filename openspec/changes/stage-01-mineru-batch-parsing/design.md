# Design

## Context

参见 [proposal.md](proposal.md)。8份139页PDF已复制并校验，物理页号按1起算；原件未变更。首批名单为air-01（臭氧方案7页）、water-02（灌溉标准11页）、air-03（2026空气标准10页）。已有JSON是本地清单，不是MinerU输出。

用户已要求首批在线解析，聊天中出现的Token需要轮换，`.env`仅由用户本地填写；当前无解析客户端或真实任务记录。现有离线评分器不加载环境配置，也不接收原始PDF清单。

## Goals / Non-Goals

**Goals:** 取得完整可追溯解析包，证明三类样本可以被解析及检查；建立批量任务的有限恢复能力，明确部分成功与缺口。

**Non-Goals:** 不自研OCR、清洗覆盖原件、全库上传、建立PG表、生成金标、向量化或构图。不要求此阶段保证语义零遗漏或支持所有MinerU历史协议。

## Decisions

1. **采用精准解析、保存原始包。** 用户提供的精准接口可交付JSON/资源，而轻量接口只有Markdown；后者缺少本轮需要核对的结构信息。优先评估`vlm`，执行前核对官方协议和实际支持，记录最终参数，不把API版本当模型或JSON版本。
2. **先核实现成接入，再补编排。** 评估固定版本LightRAG的MinerU客户端及转换边界；可提前引入依赖，但若现成入口会隐式构图或增加模型调用，则只使用独立解析入口或官方HTTP接口。RAG-Anything只有实际降低格式适配成本才引入，不以少依赖为理由先重写。
3. **内容与任务分离。** 以源SHA-256、解析配置和请求记录识别处理意图；返回任务ID后立即持久化。超时分为“已知任务可继续查询”和“提交结果不确定”，后者暂停核对，不将本地幂等键误称为服务端恰好一次保证。
4. **每份隔离保存。** 在解析后目录按批次/样本ID存原始ZIP、解压结果和脱敏状态。重复执行先读记录；损坏或未知文件保留检查证据，不覆盖有效结果或原PDF。安全解压拒绝越界路径、符号链接及超出预设数量/体积上限的包。
5. **授权白名单与秘密隔离。** 首次仅3份28页，每份最多1个新任务，仅现有免费额度，新增费用或扩量先确认。凭证只在进程内加载，不能写入命令参数、请求转储或日志；第三方上传/下载地址不附带MinerU Authorization，不记录可用签名链接。
6. **解析与清洗分开。** 本阶段保留上游内容，不自动删除页眉、表注或附件。检查输出真实schema、页码基准、资源引用、章节和表格。下一阶段才按已核实协议生成规范化原文块，原始包一直保留。

## Risks / Trade-offs

- 上游JSON版本或轻量/精准输出差异 → 保存真实样例、固定适配版本；未知类型或缺失资源作为缺口，不静默吞掉。
- 解析任务在客户端退出后仍计费 → 保存任务标识和不确定状态；有限查询，禁止无限重提及自动扩量。
- 页数齐全但表格数值或阅读顺序错误 → 对照原PDF的指定页和全文件结构，下载成功不等于解析验收通过。
- 公开外观不代表完整来源/效力审查 → 保留本地来源记录，发现受限标记或新资料时停止外发；不自行添加桌面文件。

## Migration Plan

不移动或重写原件。首次运行创建独立输出批次；失败保留任务状态与原始结果，修复后只恢复查询/下载。更换解析参数须创建可区分的新产物版本，并在新增提交前确认范围与额度。

## Handoff

- 当前已验证：8份PDF139页、哈希清单、中文输入/输出目录和首批3份28页范围。证据：[inventory.json](../../../data/local/原始文档-解析前/inventory.json)。
- 当前阻塞：Token轮换及安全本地配置、实际接口与免费额度核对；本轮不读取密钥或提交请求。
- 下一动作：先检查输出目录及历史任务，再完成 [tasks.md](tasks.md) 中首个未勾选项。不要重新收集全部样本或安装数据库。
- 交付证据：每份源哈希、解析配置、脱敏任务状态、ZIP哈希、资源清单、实际schema记录、页码/表格抽查结果、失败/待确认清单；预期均落在本地解析批次目录，当前尚未生成。
- 完成后交给阶段02；即使3份都成功，也不得自动提交剩余5份。失败样本不可凭下载包存在而标为通过。
