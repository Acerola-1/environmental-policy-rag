## Goals / Non-Goals

**Goals**

- 同一逻辑文档可保留多个不可变内容版本；每个内容版本可保存多个独立、可追溯的解析产物版本。
- 不损失来源定位、原文、表格、脚注、附件及失败状态；未知法律信息不靠默认值补齐。
- 批量入库可隔离失败、有限重试；已保存块可固定版本不重不漏地读回，父章节扩展保持同源。
- 用真实 PG 的正常、失败、重复与版本边界测试证明第一版闭环。

**Non-Goals**

- 不实现 OCR、图构建、问答、向量检索、Redis 缓存或全局索引发布协议。
- 不将全文读回成功解释为 PDF 全部正确解析、法律有效性已核实或语义零遗漏。
- 不上传其余5份样本或扩展整库；不改变既有容器、安全设置或原 docs。

## Decisions

### 1. 分离内容身份、解析身份与管线配置

采用 `doc_id` 表示逻辑文件，`version_id` 表示不可变内容版本，`parse_version_id` 表示该版本的一套不可变解析产物；解析管线/模型/转换器版本作为元数据记录，不等同于政策修订。原件哈希、产物哈希、参数指纹和来源审阅记录分别保留。

相同原件重命名或同产物重复导入不新建内容版本。同一内容换解析器或修复转换会形成独立解析版本，旧块仍可读。不能仅凭 OCR 文本差异认定法规修订，也不能只凭文件名判断逻辑文档家族；不同载体是否同一政策内容需人工确认后登记关系，未确认保持独立待核实身份。相较“一张版本表覆盖全部变化”，该方案多存元数据，但能区分法规变更和解析改进。

### 2. 稳定块身份有明确边界

`block_id` 在同一不可变内容/解析版本中全局可定位，依据冻结的来源定位及转换规则分配，重复导入不得变化；不得只用文本哈希、页码或 Qdrant point ID。来源定位同时记录原件哈希、实际产物位置、物理页号与可得的源块标识/区域；字段存在性以真实产物为准，不虚构坐标或源 ID。物理页从1开始，印刷页码另存，跨页范围不压成误导性的单页。

块顺序在 `(version_id, parse_version_id)` 内唯一、稳定；父块必须同一内容/解析版本且无环。重解析改变分块时允许新 block ID，通过明确的一对多/多对一或未匹配映射连接旧来源，不能伪称任意重解析仍有相同块身份。保留引用文本与表格结构，不用摘要替换原文。未知类型和无法转换项进入缺口清单，不静默丢弃。

优先复用 stage-01 核实的固定版本 LightRAG/MinerU 转换能力，若不满足映射要求只补必要适配，不自研 OCR，不隐式构图。

### 3. 不确定性不是空值即通过

规划 schema 版本化扩展，日期采用“值 + 已知/unknown 状态 + 核对依据”；unknown 必须无编造日期，发布日期不能代替生效日。废止时间未知与明确无已知废止记录分开表达。已知有效期采用左闭右开边界，允许有依据的追溯生效；法律关系依人工核验，不由哈希推断。

解析状态至少能表达 complete、partial、error；另存页/附件缺口、转换失败、预期可保存块清单及实际保存数量。零块失败允许登记失败记录，但不可冒充可用全文。写入成功只表示接收到的合法块已持久化；原包下载齐全也不等于 PDF 解析完整。未知日期的材料可存储和显式版本读取，但不能在未核实的有效时点范围中被默认为有效。

既有 smoke 数据继续按旧契约解释；不得为了兼容而把新数据强制改成 complete 或给日期填哨兵值。导出单一评测视图时每个内容版本固定一个解析版本，并携带 schema/解析版本映射，避免旧的版本内顺序唯一约束被多套块冲突破坏。契约实施需按 AGENTS 同步 `docs/05-data-contracts.md`、校验器、测试与样例，保留原说明与迁移依据；本轮仅规划，不修改这些文件。

### 4. 事务粒度是单个内容版本的解析批次

批量任务按文件/解析版本分别提交事务；版本记录、该套块、父引用、来源映射及成功计数原子提交。已声明 partial 的解析产物可作为完整“接收集合”提交，同时保留 partial 状态；数据库写入途中失败则回滚该套集合，不能留下半套却标成功。

幂等标识绑定内容版本、解析产物身份与转换参数指纹；同标识同内容重试返回既有结果，同标识不同内容显式冲突，禁止覆盖。并发重复由数据库约束与事务保证不增重复块，不宣称外部链路恰好一次。失败记录在成功数据事务之外持久化，保留可重试分类及有限次数；一个文件失败不回滚其他已成功文件。不选择整批单事务，以降低重跑成本和错误传播。

### 5. 固定解析视图的游标与父章节读取

读者指定内容版本，并显式选择解析版本；若使用默认解析版本，首次响应必须解析并固定它。游标绑定内容版本、解析版本和最后阅读顺序，后续不能切换版本或随“最新解析”漂移。限定每页大小，拒绝非法 limit、负顺序、伪造或跨版本游标；使用唯一顺序推进，而非相关性排序或不稳定 OFFSET。具体方法名与调用签名待实现阶段确认。

每页返回版本身份、块、后续游标、遍历状态与解析缺口；结束时可对照该冻结视图的预期已保存块数/集合校验。不存在的版本与合法零块失败记录可区分；不能自动回退到最新版本。重新开始相同视图应得到相同顺序与 ID，历史版本不因废止而从显式读取中消失。

父章节扩展按被冻结的父子关系取章节及后代块并按顺序返回；无父章节时明确只返回自身/无父状态，不偷偷扩大全文。跨版本、跨解析版本或循环父引用必须拒绝；父章节完成不等于全文完成。

### 6. 第一版验收以真实 PG 和对照证据为准

未来在确认连接方式和授权后复用既有 PG 的隔离测试命名空间，不重装、不清既有库。采用有界页大小和首尾页、跨章节、表格、脚注/附件、历史版本样本核验事务、重复并发、失败重跑和读取集合一致性。SQLite/mock 只可辅助单元验证，不计为 PG 集成通过；PG 不可用则明确阻塞。

输出分列 `saved_blocks_read_complete`、解析状态及解析缺口。前者只能证明已保存集合读尽，后者需要原件和解析产物抽查；缺口仍在时不得给出“原 PDF 全量完整”。对应 [验收](../../../docs/07-acceptance-and-evidence.md) G1-2、G1-3、G2-1 以及本阶段幂等子集，不能据此勾选后续更新治理。

## Risks / Trade-offs

- 上游真实 JSON 未到位：只能冻结不变量，字段适配和 API 留待验证，不能写假兼容层。
- 不同解析版本可能改变块边界：不承诺跨重解析 ID 永久不变，保留历史视图和显式映射，金标必须固定解析版本。
- 不明日期/解析缺页可能阻塞后续正式题集：允许保真存储但限制有效性判断，不把质量问题转成缺省值。
- 单版本原子事务可能较大：先在授权小样本测量；若需分段暂存，必须最终原子可见，不把中间分段当完整发布。
- PG 连接及隔离权限未核实：本轮不探测；没有真实集成证据则第一版验收未完成。

## Migration Plan

实现前审阅上游冻结产物与本 spec；形成带 schema 版本的契约差异和旧 smoke 兼容规则。先用独立测试数据核验，再导入首批实际成功/部分成功产物；不覆盖历史原件与旧解析集合。失败可单文件重跑，回退通过继续读取旧冻结视图完成，不依赖清库。
