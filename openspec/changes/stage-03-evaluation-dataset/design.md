## Context

[步骤](../../../docs/04-step-by-step.md)要求从实际样本列题并建立人工金标，再做真实基线；[评测说明](../../../docs/06-evaluation-and-load-test.md)要求开发调参与封存测试分离、公开和合成分开、失败题进入统计。[现有契约](../../../docs/05-data-contracts.md)与实现仅支持 `split=smoke`，校验引用子串、范围与版本，不能证明法规真实性或语义支持；评分器读取外部 judgments，始终不认证模型执行来源。

当前只有既有离线验证/评分工具以及8份139页的PDF副本，首批 air-01/water-02/air-03 共28页未解析；没有人工题集、完整存储或模型 benchmark。stage-02 亦未实现。不能因为文件都涉及环境政策，就认定它们覆盖独立地区、文档家族、真实历史版本或适合 holdout。

本轮只写规划，不读取原件之外的受限资料，不联网核实法规，不采集新文件、不标注假金标、不跑测试/模型、不改原 docs。下列数据及证据子目录均待创建。

## Goals / Non-Goals

**Goals**

- 冻结数据版本、内容/解析视图、开发集和封存集的分组规则，使结果可复核且不因同源改写泄漏。
- 人工 gold 独立于模型预测；judgments 对实际预测独立裁决，保留原文、条件、单位和法律时间边界。
- 在现有工具上扩展 schema 和评分输入，保留 smoke 自检、逐题失败、重复和错误版本的统计规则。
- 数据不足时给出明确阻塞与开发结果边界，不制造正式 benchmark。

**Non-Goals**

- 不保证现有8份能组成独立封存集，不采购或批量扩展真实数据，不把合成政策冒充真实版本。
- 不实现检索服务、不运行模型、不设想已达到的准确率或并发指标。
- 不用程序校验代替法律审查，也不用 gold 覆盖的有限条目代表现实世界全部政策。

## Decisions

### 1. 按家族分组，相关版本不得跨 split

规划 schema 显式支持 `smoke`、`dev`、`test`，其中 test 只有通过冻结和访问控制流程后才称封存测试。文档家族作为分配单元，同一政策所有修订、重命名/重复副本、重解析视图、派生问题及近似改写进入同组；题目涉及多个家族时合并关联组，避免一条跨文件题把来源连接到两个 split。版本对比题使用的历史/当前版本必须在同组。

先查家族、版本关系和源哈希，再定划分与封存哈希，不做随机按题切分。人工疑似重复未解决前不允许宣称划分独立；基于真实文档改写的合成题也需记录来源关联，不能以 synthetic 标签掩盖泄漏。代价是独立样本数减少，但比表面样本量更可信。

封存隔离的是开发者对题目、金标及测试反馈的调参访问，不是禁止检索系统在正式测试时读取已冻结的授权源文档。运行时可见检索材料必须事先声明，且不得把测试题目、gold 或 judgments 编入检索索引/提示示例。冻结后变更形成新数据修订号，接触封存答案并据此调参后不能继续称原封存集独立。

### 2. 现有样本不强凑 holdout

先做现有8份的家族/版本与授权可行性审查，不默认都可解析、都属于可外发 public 或都能进入评测。首批解析范围仍只有3份28页，其余5份的解析/上传不因本变更而授权。

若无法划出足够独立且可核验的封存组，交付开发诊断题集、候选划分和缺口清单，把封存题集交付标为阻塞；不得将随机分题或重复文档改写作为替代。协议和开发数据可供 stage-04 做开发基线，独立质量结论继续阻塞，不把这种局部交付称本阶段全部验收通过。需要扩样时仅提交范围、来源类别、预计标注量和授权需求，不执行采购、联网下载、复制、上传或付费调用。

### 3. 来源分类与法规版本人工核对先于正式 gold

public 与 synthetic 使用独立目录、manifest、案例、运行和报告；本地清单 `inventory.json` 不能直接当评测 manifest。对真实法规人工逐项核对标题、文号、地区、发布日期、生效/废止日期、替代关系及原页依据，区分物理页与印刷页；OCR/解析内容不是法定真实性证明。unknown 日期、无法确认的替代关系保留待核实，不能通过捏造日期满足旧校验。

正式时点题须有经核对的有效期与地区依据；历史问题使用当时有效版本并不算错误版本。无法确认的题进入可追溯 pending/诊断清单，不伪装成无答案题或正式金标。若原件含有证据而解析缺块，保留原件定位和缺口但不伪造 block ID；块映射修复前不得将其作为已完成的块证据 gold。正式题的排除/待核实数量及原因须随数据发布，不能只展示容易题。

synthetic 必须标识虚构地区/政策及生成与人工复核方式；边界夹具只能证明工具行为，不证明真实法规版本正确。

### 4. Gold 与 judgments 分离，复核可审计

Gold 在看待测模型输出之前依据原件独立标注，包含明确 scope、可回答性、条目、条件、阈值/单位及固定内容/解析版本的引用。标注人员与复核记录可审计，争议解决前状态为未决。AI 可给草稿，不能直接定稿；同一模型生成答案和金标不算独立验证。

Judgments 在收到预测后按冻结标准逐条判断匹配 gold、语义正确、引用支持和错误版本，由独立于答案生成流程的人工复核，不采信预测自报的 correct 或 citation_supported。引用子串存在只证明出处，不能自动证明条件/数值一致。允许记录裁决分歧和修正，但不得悄悄修改 gold 迎合模型；gold 修订产生新数据版本，旧结果仍关联旧版本。复核人力未落实时不生成“已人工审核”标记。

### 5. 扩展现有工具而非另起评分口径

现有 `scripts/validate_dataset.py`、`scripts/score_eval.py` 与 `tests/test_eval.py` 为后续扩展入口。stage-02 拥有存储/解析契约，stage-03 负责 split、分组、冻结、标注和评测运行规则；先对齐上游 schema 再扩展，不能两阶段分别定义互不兼容的 unknown/parse_version 语义。

扩展校验器对单次输入的 dataset_kind/split 一致性、家族版本分组、冻结哈希、引用范围和独立复核记录做确定性检查，错误给出文件/行/字段而非降级为成功。仅有标志位不能自证人工核对或封存，需要关联审阅材料；算法不能保证人没有泄漏，应如实说明流程限制。

评分器继续只计算外部 judgments。保留 `smoke`、demo 标识和 `is_model_benchmark=false`；不得因改名为 test/public 或输入自报调用模型就自动升级为 benchmark。未来真实模型运行由 stage-04 的完整推理/裁决证据包说明，单独评分 JSON 仍非认证。实施契约更新时须按 AGENTS 同步 `docs/05-data-contracts.md`、样例与测试，保留原说明与变更依据；本轮只创建OpenSpec计划，不改原 docs。

### 6. 覆盖失败而非只求成功分数

题型矩阵覆盖普通事实、跨章节枚举、表格/单位/脚注/附件、真实历史时点/替代关系、错误地区/版本、无答案，以及解析缺口和 partial/error 输出。真实样本不能覆盖的类型明确记缺口；合成夹具独立补边界，不混入 public 指标。

冻结正式题集内每题必须有 prediction，失败、超时、空输出保留 status 与原因；超时映射为 error 并带原因，不能反向把题改为 `answerable=false`。每个输出项必须有 judgment，缺题/缺裁决拒绝评分。相同 gold 多次命中只增一次分子，重复预测保留在精确率分母。partial/error 可贡献已裁决的局部召回，但不能算完整覆盖；无答案答对须 complete 且无输出。

沿用 [指标定义](../../../docs/06-evaluation-and-load-test.md)：micro/macro 召回、精确率、全项覆盖、完全正确、无答案正确率、引用支持和错误版本率；分母为零输出 null。分别报 dataset_kind/split、题量、逐题结果和未覆盖范围，不预先虚构质量阈值或成绩；模型质量门槛在运行前由后续阶段确认。

## Risks / Trade-offs

- 8份资料并非8个独立家族；即使成功解析首批3份，也可能完全不具备独立 holdout，不能以任务完成压力降低独立性定义。
- 真实版本/日期需要人工核对，现有样本外观公开不保证合法可用；未知继续阻塞正式时点题。
- 独立人工金标和裁决耗时，复核责任人未确定时交付流程而非假签名。
- 未解析证据无法引用真实块：隔离诊断缺口并说明覆盖限制，不通过编块或删除失败题抬高分数。
- 封存访问仅凭本地流程不能防止所有人为泄漏，需要审阅记录和重封存策略；不声称工具提供安全隔离服务。

## Migration Plan

先锁定旧 smoke 的确定性输出，再与 stage-02 对齐 schema，增加 dev/test 和分组/冻结校验；已有 smoke 文件及 demo 保持原用途。按样本修订生成新目录，不覆盖原件、旧题集或旧金标。开发数据先经人工复核；封存门槛未满足则保持阻塞，待另授权的样本扩展和核对完成后生成新修订，不重命名开发集充数。

## Handoff

- **当前事实**：8份139页仅复制，首批28页未解析；无人工金标或封存集，只有离线 smoke 校验和评分记录。stage-02 尚未实现，PG/Qdrant/Redis 虽已部署但本项目未连接，本阶段不要求启动它们。
- **入口**：审阅 [stage-02 proposal](../stage-02-versioned-document-store/proposal.md) 和 [spec](../stage-02-versioned-document-store/specs/versioned-document-store/spec.md)，检查实际通过证据而非仅文档；取得冻结块导出、内容/解析版本、来源映射及缺口后，先做家族/版本可行性检查。以本 change 的 `tasks.md` 为执行清单。
- **阻塞**：真实块与有效期核对缺失；独立标注/复核人力未确认；现有样本是否足够独立待判断。新数据采购、样本扩展及新增解析不在授权内。
- **未来交付证据**：`data/public/<dataset-revision>/`、`data/synthetic/<dataset-revision>/`（子目录待创建）保存各自 manifests/blocks/cases、分组/封存摘要、标注复核与 pending 清单；`runs/<dataset-kind>/<run-id>/`（待创建）保存 schema/工具版本、校验及手算回归、失败夹具计分、裁决协议和通过/阻塞状态。不能提前生成貌似真实模型预测或签署人工记录。
- **下游接手**：stage-04 获得冻结的开发题集、可用封存集或明确阻塞、全套评分与裁决协议。仅开发诊断时可开展获准的开发基线，但不能标封存质量验收通过；本阶段不提供真实模型 benchmark。
