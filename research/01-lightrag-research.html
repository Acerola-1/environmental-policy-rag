02 / 实际检索模式

README 列五种检索模式；SDK、REST 还接受 bypass，默认均为 mix。下表描述关键词正常提取时的主路径。[3][4]

模式检索入口执行差别
naive原问题 → 文本块向量不查图；块候选可重排、截断。
local低层关键词 → 实体向量取实体及相邻边，再映射来源块；实体按相似度，关联边按度数、权重排序。
global高层主题词 → 关系向量取关系及端点实体，再映射来源块；不是扫描全库，也不是社区报告。
hybridlocal ＋ global交替合并实体、关系并去重；仍会取图关联的原文块。
mixhybrid ＋ 原问题的块向量召回合并图关联块与直接命中块，再统一重排、限额。
bypass无检索直接调用 LLM；检索数据接口返回空数据。

关键词通常由 LLM 提取，也可显式传入；缺词存在回退分支。图关联块可按 VECTOR 相似度或 WEIGHT 加权轮询筛选。这里的 hybrid/mix 不等于“BM25＋向量＋RRF”：该路径实际采用轮流合并与去重，并无 RRF 打分。

03 / 已核实机制与前提

  • 构图与更新：LLM 逐块抽取实体、关系，合并描述并更新图及向量索引，以 source_id 连接来源块。新增内容可增量合并；删除文档会清理贡献，并利用剩余块的抽取缓存重建受影响图元素。依赖抽取质量、缓存及来源映射完整性，不等于自动管理法规时效。[5]
  • 重排与引用：重排针对候选文本块，须启用且配置重排函数；未配置或失败会回退，之后仍受分数阈值、块数及 token 预算限制。引用由块的 file_path 映射生成；REST 默认返回引用，SDK 默认关闭该开关，/query/data 可取证据数据。引用不等于逐句正确性证明。[3][6]
  • 运行与解析：需要抽取/回答模型、embedding 及图、向量、KV、文档状态存储；更换 embedding 须重建相关向量。小规模试验可从默认本地存储起步，扩大语料时需另行评估存储、并发和恢复能力；本次没有测定其规模上限。当前已有标题/表格感知的 P 分块，但须解析器产出结构化 sidecar，缺失会退化，不能认为上传 PDF 就自动无损。[1][7]

04 / 优势有哪一级证据？

作者宣称：更全面的跨文档问答、更低检索及增量更新成本。架构可推导：实体/关系可补充词面不相似的关联证据，mix 保留原文通道；代价是额外抽取、索引与错误传播。作者实验：UltraDomain 四领域、每域125题，主要由 GPT-4o-mini 比较全面性、多样性等回答胜率；这不是中文环境政策条款召回率。其成本比较也不能直接等同当前端到端成本。本次没有实测收益。[2]

05 / 对“某年某市有哪些措施”的判断

图关联可能找回散落在多份文件中的措施，但global 不保证全量，mix 不保证无遗漏。解析漏掉标题、表格或附录，抽取漏关系，同名实体误合并，图来源数上限、top-k、重排过滤和上下文截断，都可能损失条款；生成阶段还可能漏列或混淆新旧版本。

当前查询上下文是图信息与选中块；虽有 full_docs 存储，默认查询不自动返回命中文档全文。优先另建文档/条款目录，明确“当年发布”还是“当年有效”，按地区、生效/废止期筛选，再按文档ID遍历正文、表格、附录并汇总去重。该穷举通道需自行实现；只有限定语料和规则后才能评估完整性，图检索只是补充发现手段。

06 / 小范围个人实验路线（待实施）

以下规模与次数均为实验建议，不是已完成数据或成绩。仅用公开文件，不复制公司私有语料。

  1. 定标：选2市、3年约60份政策，含修订版、表格与附录；设计30题，10题调参、20题封存测试。人工通读限定语料，标注措施/条款ID、版本和证据页，复核金标，加入无答案题。
  2. 对照：A复现现有“混合检索＋RRF＋rerank＋父章节召回”；B使用 LightRAG mix。同文档、同 MinerU 解析与分块、embedding、重排模型、回答模型和上下文预算；记录各路候选数，避免只给B更多预算。用 naive/hybrid 作模式消融；P分块另测，不与图收益混算。
  3. 验证：分别测候选、最终上下文及答案的条款召回率；报告答案精确率、全项覆盖题率、引用正确率、时效误配率，以及 p50/p95 延迟、token/费用与索引成本。对照使用相同缓存条件，建议重复3轮；按题配对报告，不只选成功案例。
  4. 归因：A、B分别加同一目录过滤/全文遍历通道，隔离其收益；再做一次新增/替换/删除回归。留存源码提交、配置、语料清单、金标、原始检索日志与失败案例，按解析→抽取→召回→截断→生成定位遗漏。

完成并验证后才能使用的个人项目模板：

“独立实现环境政策条款完整性评测，对比混合检索与 LightRAG，建设版本约束及证据回溯；在［公开测试集］上记录［实际指标及代价］，分析遗漏来源。”

07 / 经历边界

现有公司实践：3年后端，首年Java、之后Java与Python Agent/RAG并行；正式上线Agent的相关负责人；Spring AI按模块封装Java数据服务为MCP；约4.4万份环境文件，已实践MinerU、分块、混合检索、RRF、rerank及父章节召回。以上为用户提供事实。
