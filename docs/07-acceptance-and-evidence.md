# 验收与证据清单

逐项填写：未开始 / 已实现待测 / 通过 / 未通过 / 不适用，并附证据路径。文档中描述一项能力不等于实现了它。

| G1-3 | 原件与解析结果对照过，缺页缺附件可见 | 页面抽查、表格/脚注/附件失败清单 |
| G2-1 | 指定版本可按顺序取回全部已保存块 | 首尾页、跨章节、表格、附件的读取测试 |

| G7-1 | 可公开的个人项目事实已审核 | 代码、语料、评测、复现方式和真实贡献清单 |

## 当前交付不能提前勾选的内容

模型接入、完整RAG服务、公开数据评测、图谱消融、生产容量与更新治理均尚未验证。仅因为本目录有教程、样例或配置文件，不能把相应格子标成“通过”。

离线自检实际结果由完成时的运行日志证明；不得将固定脚本输出替代一次真实执行。

## 本地验证完成后的交接包

1. 哪个代码版本、哪批数据、哪个配置可复现。
2. 源文件授权与公开/合成划分，数据版本及哈希。
3. 模型服务、请求协议、embedding/重排及上下文限制。
4. 完整题集的输出与失败记录，金标和裁决方式。
5. 各阶段检索trace、指标表与至少若干失败案例。
6. 成本与负载条件；没有测过的维度明确留空。
7. 增删改与失败恢复的日志和已知限制。
8. 哪些素材可以公开展示、哪些仅限本地。

## 简历采用门槛

- “实现某功能”：代码存在、能运行，且有正常和失败测试。
- “改善完整性”：固定语料、独立金标、对照实验及原始结果可核查。
- “支持并发/吞吐”：负载脚本、环境、成功标准与错误率完整，不能用理论推导。
- “增量更新与一致性”：不只是新文件可插入，还测过修订、删除、共享来源和失败恢复。
- “生产上线”：仅在真实公司或部署环境发生过，不能用本地演示替代。

若达不到门槛，可以描述“个人原型”“方案设计”或“本地实验”，而不是提高成果强度。
