# 数据准备、合成与标注

## 1. 遗留文件先盘点，不直接喂模型

2026-09-23已按用户授权只读盘点桌面“水环境原始资料集”“大气环境原始资料集”，选取8份PDF复制到 `data/local/原始文档-解析前/`，共139页。原路径、内容哈希、页数、特征及重点检查页保存在 `inventory.json`；源/副本哈希一致。原件未删除、改名或改写，尚未上传。网页来源旁证保留路径，未作全面权利或效力审查。

“在桌面上”不能证明可以上传；“网上公开”也要核对来源与使用条件。客户文档、内部批注、账号、联系人等进入 `data/local/` 隔离区，不进入外部 API。无授权来源时，先使用公开发布渠道重新下载或使用合成材料。

`data/public/raw/` 和 `data/local/` 被 .gitignore 排除，但这只是 Git 行为，不是访问控制或上传拦截。

## 2. 两条数据线

| 数据线 | 用途 | 能得出什么结论 |
|---|---|---|
| public | 来自可靠公开来源的真实政策、标准及附件 | 在明确样本范围内的业务效果；不能自动推广到全部 4.4 万份历史资料 |
| synthetic | 人工或 Agent 构造的虚构政策与边界场景 | 流程、错误处理、版本/表格/漏项测试；不能宣称真实业务准确率 |

每行记录带 `dataset_kind`；目录、检索集合、评测运行和结果都分开。评分器拒绝混合 public/synthetic。若以后做混合训练或压力输入，也必须单独命名和说明，不与真实质量基准混报。

## 3. 从少量公开资料起步

当前已选8份真实PDF、139页作为开发样本；首批仅解析臭氧方案、灌溉标准、2026空气标准，共3份28页。先验证文字、表格脚注和扫描件，再逐步扩大；不要为凑数先收集60份或用AI生成大量PDF。版本对、较长附录等其余样本稍后接入，详见阶段教程。

每份文件核实：文号、发文机构、适用地区、发布日期、生效日期、废止/替代关系、附件是否完整。缺字段保留未知，尤其不要用发布日期代替生效日期。

## 4. 文档标识与解析保存

1. 先给逻辑文件分配 doc_id，再给每个版本分配 version_id。
2. 保存原文件和内容哈希；不要仅靠标题判断重复或版本。
3. 核对所用 MinerU 版本，保存实际解析结果和图片/表格等资源。
4. 转换成统一 blocks：原文、块类型、顺序、父章节、页码和表格 HTML。
5. 手工比较若干原文页面与解析输出，重点检查表头、单位、脚注、跨页表格、目录误识别和附件。
6. 标记解析失败与资源缺失；只保存成功块会使后续“全量遍历”产生假完整。

官方当前协议与旧部署可能不同，本目录的 blocks 是应用规范，不照抄某版 MinerU 字段。

## 5. Agent 可以怎样造可控数据

先写“潜在事实表”，再生成文档，最后人工核对。事实表记录每条措施、适用条件、版本有效期、原始来源块与预期回答范围。

建议的合成场景：

- 同一问答所需十条措施分散在多个章节、表格和附件；关键词不完全一致。
- 两份相似政策中有重复措施，但适用对象不同，不能盲目去重。
- 旧版阈值与新版阈值冲突，历史问题应返回旧版、当前问题应返回新版。
- 同名虚构城市/机构或相似缩写，测试图实体误合并。
- 某条只出现在表格脚注，或需要保留单位与条件。
- 问题的地区、时间或主题在限定语料中没有答案。
- 附件损坏、块抽取失败、模型超时，测试“部分完成”状态。
- 文档里包含“忽略指令”等干扰文本，验证系统将其作为资料而非命令。

生成要求：标题含“合成”，使用样例市甲/乙等虚构地名，`source_uri` 使用 `synthetic://`。不要伪造真实公文编号、官方印章或声称是真实法规。

可给 Agent 的任务模板：

> 根据我提供的潜在事实表生成一组明确标记为合成的测试文档。每项事实必须保留；允许跨章节分布、同义改写、表格化，但不能更改条件和版本关系。输出文档和事实—证据映射。不要替我宣称金标已通过人工审查，也不要生成实际项目成绩。

## 6. 避免“同一个模型给自己判满分”

- 文档与金标由同一模型生成后仍需逐项核对；生成器的自述不是证据。
- 金标不依赖待测系统的输出。先定范围和标准答案，再跑系统。
- 模型可辅助标注，人工负责处理分歧、条件差异和引用支持。
- 不让生成样例同时构成全部测试集；公开真实文件用于检验泛化。
- 系统开发与最终裁决最好分角色，保存修改痕迹。

## 7. 问题与金标

每个问题先写清 scope：地区、时间口径（发布/有效）、纳入文件版本、是否包含上级政策，以及问题要“措施”还是“标准”。

拆分原子条目：同一措施的不同措辞不算两条；相同数值但适用对象/单位不同不能合成一条。每条金标含 item_id、原文依据、块 ID 和引用。无答案题的 gold_items 为空，并写清受检范围。

当前离线样例使用 `as_of` 表示有效时点，区间为 `[effective_at, repealed_at)`；生产扩展发布日期范围等规则时同步更新契约和测试。

## 8. 划分与封存

开发集用于改 Prompt、阈值与融合权重；测试集在选型前封存。按文档家族/版本分组，避免同一文件或近重复修订版同时进入两侧。smoke 小样例只是工具自检，不能当封存测试集。

测试集被开发者反复查看后，应记录其污染状态并补新的留出集。小样本结果只报告具体范围，不制造“全行业 95%”结论。

## 9. 数据验收

用 [校验器](05-data-contracts.md) 检查字段、ID、版本、引用与集合，再人工抽查语义。结构校验通过不能替代内容真实性、正确性或授权核验。
